# 已结束场次清单与按场次导出方法(room_id=7000000000000000002 账户,2026-09-04 实测)

> 场景:用户想在“抖音生活服务/本地直播专业版”直播大屏导出指定场次。本次联调默认导出
> 了 09-02 11:16–19:00 这场(room_id=7000000000000000002);用户截图目标是
> **09-04 09:04 开播的一场**(截图时 15:28)。以下说明“怎么枚举该账号可回放场次、
> 每场对应哪个 room_id、怎么按场次导出”。

## 1. 关键结论

- 本账户(示例商家账号)可回放的已结束场次**每个场次 = 一个独立 room_id**(同一账号
  一天多次开播,每次生成新直播间 id)。因此“指定场次导出”= 找到那场的 room_id 后执行
  `python main.py export --room-id <该场room_id>`(默认展示该房间唯一/最近已结束场)。
- 用户截图目标场(09-04 09:04 开播)已定位:**room_id=`7000000000000000001`**,
  实际整场 **09-04 09:04:21 – 19:00:28**(截图 15:28 为直播中途)。该场导出已验证:
  **597 行(09-04 09:04–19:00)、非零分钟求和 2000.00 元 = 页面直播间成交金额 2000 元,
  三条内置校验通过**,产物 `data/outputs/live_0904_7000000000000000001.csv/.xlsx`。
- 09-02 场(room_id=7000000000000000002)导出产物
  `data/outputs/live_7000000000000000002.csv/.xlsx`(465 行,1350 元,校验通过)。

## 2. 枚举机制(页面 + 只读接口,2026-09-04 实测)

页面路径:
1. 大屏顶部“场次 09-02 …”处 **hover** → 弹出菜单含“查看场次”与“查看完整复盘”;
2. “查看完整复盘”以新窗口打开复盘页
   `https://eos.douyin.com/livesite/live/room/analysis?room_id=<room_id>&create_time=<开播epoch>&enter_source=live_screen`,
   其左侧“直播记录”按天列出该账号场次(开播时间/时长);
3. 底层场次列表接口(账号级、按“东八区本地日”查询,只读 GET):
   `https://eos.douyin.com/data/life/live/room/paged/?start_time=<当日00:00epoch>&end_time=<当日23:59:59epoch>&page_size=50&order=2&scene=1`
   每项:room_id、live_id、status(=4 已结束)、start_time、end_time、title、biz_room_category 等。
   (注意:跨多日区间会返回“参数不合法”,需按天查询;证据见 data/probe/t9_room_paged_raw.json、
   t9_session_switch.json、t9_sessions_evidence.json)

“查看场次”打开的历史页 URL 形态(JS 静态证据):
`https://eos.douyin.com/dp/liveScreen?room_id=<id>&enter_from=eos_live_history_page`
(实际进入大屏后仍默认展示该 room_id 的场次;场次明细以复盘页 create_time 为准。)

## 4. 按场次导出(命令)

```powershell
# 指定场次 = 指定该场的 room_id(已登录、有权限)
python main.py export --room-id 7000000000000000001 --excel   # 09-04 09:04 场(用户目标)
python main.py export --room-id 7000000000000000002 --excel   # 09-02 11:16 场
# 其余场次同理,把 room_id 换成上表“导出用”列即可;校验失败会拒绝输出并给明细
```

## 5. 局限与建议(如实)

- 本工具/页面侧把“场次”与“room_id”一一对应(本账户实测);若某场次无法用 room_id
  默认选中(如同一天该 room 有多场、或回放未就绪),请以复盘页 URL 的
  `room_id` + `create_time`(开播 epoch)为准,把该链接/参数提供给开发者进一步适配;
- 跨午夜场次(如 09-01 22:01 场)分钟时间轴 x 为 `MM-DD HH:MM`(无年份),session_date
  按行对象 time_stamp(epoch)推断,复核时注意归属日;
- 历史入口还提供 `life/api/live_screen/v5/replay/live_room_list`
  (POST, params: user_id/begin_date/end_date;含 `?download=1` 下载版)与
  `replay/live_date`(开播日历)等只读接口,供后续“按日期范围出全部场次汇总”扩展,
  本次未启用(避免引入超出本任务范围的自动批量行为)。
