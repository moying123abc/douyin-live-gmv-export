# 多账号切换:一个账号一份持久化 profile

> 适用版本:支持 `python main.py accounts` 与 `--account` 之后的所有版本。
> 本文只讲**怎么做、为什么成立、实测证据**;代码在 `accounts.py` / `auth.py` / `main.py`。

## 0. 一句话结论

"切账号" = **切 Chromium 的持久化 profile 目录**。不传 `--account` 时程序行为与升级前**完全一致**
(仍用 `config.yaml` 的 `browser.profile_dir`,默认 `data/browser_profile/`);传了 `--account spa2`
就用 `data/accounts/spa2/browser_profile/`,两份登录态互不影响。

## 1. 原理(为什么一个参数就够)

1. 抖音 / 巨量百应的登录态(Cookie:`sessionid`、`sessionid_ss`、`sid_guard`、`sid_tt`、`uid_tt` 等)
   是 Chromium 写在 **user_data_dir** 目录里的。
2. 本仓库**唯一**的浏览器落地点是 `auth.py` 的 `open_session()` →
   `pw.chromium.launch_persistent_context(user_data_dir=resolve_profile_dir(cfg), ...)`;
   所有采集入口(`extractor/sessions.py`、`extractor/trend.py`、`extractor/extra_metrics.py`、
   `probe.py`、`exporter/watch_capture.py`、`gpm_probe.py` 等)都走这一个函数、且共用同一个 `cfg`。
3. 因此只要在**配置加载之后、打开浏览器之前**改写 `cfg["browser"]["profile_dir"]`,
   整条链路就都切到了另一个账号 —— 采集层 / 导出层一行都不用改。
   `accounts.apply_account(cfg, cli_account)` 做的正是这件事:
   - 默认账号(`default` / 不传):**不动** `profile_dir` → 老用户零迁移;
   - 具名账号:改写为 `<accounts_dir>/<名字>/browser_profile`。

优先级:`--account` > `config.yaml: browser.account` > 默认账号。账号名非法时**在加载配置阶段**
就以退出码 2 拒绝(不建目录、不开浏览器),绝不静默回退到默认账号(否则会串号)。

## 2. 实测证据(2026-09 真机,不是推测)

三个实验都用同一个程序路径(`auth.open_session`)headless 打开,观察"是否判定已登录"与落地页:

| 实验 | user_data_dir | 判定已登录 | 命中的鉴权 Cookie 名 | 落地页 |
|------|---------------|-----------|---------------------|--------|
| A | 默认 `data/browser_profile` | **是** | `sessionid, sessionid_ss, sid_guard, sid_tt, uid_tt` | `https://eos.douyin.com/livesite/live/home`(右上角账号名:方寸自在SPA) |
| B | 全新空目录 | **否** | 无 | `https://eos.douyin.com/livesite/login`(页面出现"抖音扫码登录 / 验证码登录";目录自动生成 360 个文件) |
| C | 把 A 整份 `copytree` 到新目录 | **是** | 与 A 完全相同的 5 个 | 直接进 `.../livesite/live/home` |

- **A vs B** → 不同目录之间登录态**完全隔离**:空目录不会"蹭"到默认账号的登录态。
- **C** → 登录态**完全封装在目录内**,可整份复制 / 搬移:所以"扫一次码,以后 `--account` 自动复用"成立;
  同时也意味着**复制出来的目录 = 同一账号的登录态副本**,要按凭据对待。
- 本项目内的端到端复核(真机):把默认 profile 复制成 `data/accounts/probe2/browser_profile` 后执行:

  ```powershell
  python main.py sessions --account probe2 --date 09-04
  ```

  实际输出(节选):

  ```text
  [auth] 账号: probe2(profile: ...\data\accounts\probe2\browser_profile)
  [auth] 账号 probe2:检测到已有登录会话(profile 自动复用,鉴权 Cookie: sessionid, sessionid_ss, sid_guard, sid_tt, uid_tt),无需重新扫码。
  [sessions] 2026-09-04 已结束场次 1 场:
    - room_id=7681479579405011739  2026-09-04 09:04:21 ` 19:00:28  (596m)  方寸自在spa新店开业放福利啦
  ```

  即:`--account probe2` 直接复用了复制过来的登录态并列出了真实场次;
  而另一个全新名字 `probe_fresh` 判定 `logged_in=False`(隔离生效)。验证用的 `probe2` 目录已删除。

## 3. 用法

```powershell
# 看现在有哪些账号(默认账号前面带 *)
python main.py accounts

# 给第二个账号登录一次(有头窗口,人工扫码)
python main.py login --account spa2

# 之后所有命令带上同一个 --account
python main.py sessions --account spa2 --date 09-04
python main.py daily    --account spa2 --date 09-04
python main.py export   --account spa2 --room-id 7681479579405011739 --date 2026-09-04
python main.py stats    --account spa2 --date 09-04

# 单独跑观看量捕获(被 main.py 进程内调用时会自动继承当前账号,无需额外传)
python -m exporter.watch_capture --account spa2 --room-id <room_id> --date 09-04
```

- 账号名规则:**字母或数字开头,1–32 位**,允许字母数字与 `_ - .`(`spa2`、`shop-a`、`store.1`);
  Windows 保留设备名(`con` / `com1` / `nul.txt` 等)也一并拒绝。
- 想固定账号:在 `config.yaml` 写 ```browser: { account: spa2 }```(命令行 `--account` 仍优先)。
- 输出目录不变:`data/outputs` 的文件名里带 `room_id`,不同账号不会互相覆盖。

## 4. 账号登记(方便确认"现在跑的是谁")

登录成功后会自动写一份登记文件(只含账号名 / 页面账号名 / 时间戳,**不含任何 Cookie 值**):

| 账号 | 登记文件 |
|------|----------|
| 默认账号 | `data/accounts/default.json` |
| 具名账号 `spa2` | `data/accounts/spa2/account.json` |

字段:`account`、`profile_dir`、`nickname`(页面右上角账号名)、`logged_in_at`(`YYYY-MM-DD HH:MM`)、
`first_login_at`。页面账号名优先按 CSS Module 前缀选择器 `[class*='panel-profile-name']` 读取
(2026-09 实测形如 `panel-profile-name-P6wfnt`,语义前缀稳定、哈希后缀会变);读不到就留空,
且**不会**用空值覆盖已记录的昵称。

## 5. 常见问题

- **想给账号改名** → 退出后把 `data/accounts/<旧名>` 整个重命名即可(登录态跟着目录走),
  改名后 `python main.py accounts` 会按新目录名列出;不想手工搬就换个名字重新 `login`。
- **想临时换账号** → 命令上加 `--account <名字>`;想长期固定 → `config.yaml` 的 `browser.account`。
- **想删掉某个账号** → 删除 `data/accounts/<名字>` 目录(登录态一并删除)。这是**唯一**的"彻底退出"方式。
- **提示 `status_code=8 用户未登录` / 一直等待超时** → 该账号会话已过期:
  `python main.py login --account <名字>` 重新扫码即可(默认账号就 `python main.py login`)。
- **能不能同一账号并发跑两个命令?** 不能。同一个 profile 目录同时只能被一个 Chromium 实例使用,
  并发会出现抢占(第二个实例报错或行为异常)。需要并行就用**不同账号**的目录。
- **为什么不干脆用一个 profile 反复扫码切换?** 那样会互相覆盖登录态、无法并行,而且极易出现
  "以为在跑 A、其实跑的是 B";一账号一目录才是干净隔离。
- **凭据安全** → `data/browser_profile/` 与 `data/accounts/` 都在 `.gitignore` 内,严禁提交;
  程序只读 Cookie **名称**做存在性判断,永不读写或打印 Cookie 值。

## 6. 涉及文件

| 文件 | 作用 |
|------|------|
| `accounts.py` | 账号名校验 `normalize_account_name` / 路径 `account_paths` / 切换 `apply_account` / 登记读写 / `list_accounts` |
| `main.py` | 六个子命令的 `--account`、`accounts` 子命令、`_load_cfg` 里账号校验失败即退出码 2 |
| `auth.py` | 打印当前账号、登录成功后写登记、读取页面账号名 |
| `exporter/watch_capture.py` | `--account`(单独运行时用;被 `main.py` 进程内调用时自动继承) |
| `tests/test_accounts.py` | 14 个离线用例:校验/路径/优先级/登记往返/CLI 拒绝非法账号 |
