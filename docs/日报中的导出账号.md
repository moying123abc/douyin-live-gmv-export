# 日报里的导出账号:确认"这批数据是哪个账号导出的"

多账号并存时,最容易出错的地方不是登录,而是**切了账号却拿旧数据做表**:
日报只读本地 CSV,文件本身不带账号信息,光看 `live_20260904_<room>.csv`
无法判断它是 A 店还是 B 店的号导出的。本功能给日报补上这层归属信息。

## 一、两个"账号名"不是一回事

| 名字 | 是什么 | 例子 |
|------|--------|------|
| `--account` 账号名 | **本地登录 profile 的目录名**,只说明用的哪份登录态 | `1`、`spa2` |
| 页面账号名(nickname) | 巨量百应页面右上角显示的**真实登录账号** | `示例账号A` |

真出事的是后者。日报里统一写成 `1(示例账号A)`(`accounts.account_label`)。
页面账号名在登录时由 `auth.record_login` 读取登记;之后每次按天导出/单场导出
路过页面时,`auth.sync_account_nickname` 会顺手刷新一次登记
(**只改 nickname,不动 `logged_in_at`**,不会伪造一次登录)。

## 二、归属记录写在哪

按天导出(`export --date` / `daily` 自动补导出)每成功一场,就在**导出目录**写一笔:

```
data/outputs/_account_index.json
```

结构(按天 → room_id → 归属):

```json
{
  "version": 1,
  "updated_at": "2026-09-04 20:10",
  "days": {
    "2026-09-04": {
      "7000000000000000002": {
        "account": "1",
        "nickname": "示例账号A",
        "exported_at": "2026-09-04 20:10",
        "first_at": "2026-09-04 20:10"
      }
    }
  }
}
```

- 同一场重复导出:**覆盖** `exported_at`,保留 `first_at`(首次归属),便于发现"中途换过账号";
- 索引与导出文件同目录(`export.out_dir`),`.gitignore` 已忽略 `data/outputs*/`,不会入库;
- 写失败只在极端情况发生(磁盘满/无权限),**绝不影响导出本身**;
- 单场导出(`export --room-id`)产出的是 `<room_id>.csv`,没有 `live_<YYYYMMDD>_<room>` 的规范命名,
  不写索引(不猜日期/场次)。

## 三、日报里能看到什么

`daily --date <日期>` 生成的 `日报_<YYYYMMDD>` 文件夹:

| 产物 | 变化 |
|------|------|
| `日报汇总_<YYYYMMDD>.csv` | 末尾新增 `account` 列,如 `1(示例账号A)`;合计行该列留空 |
| `账号说明.txt` | 新增:逐场写 `room_id=… 账号: … 导出时间: …`;无记录场次标 **未知** |
| 终端输出 | `[daily] 导出账号: 1(示例账号A) …`;混账号时另有 `[publish] 注意:本日报混合了 N 个账号的数据` |

老数据(本功能上线前导出的 CSV)**没有归属记录**:`account` 列留空、说明里标"未知",
不会根据文件名/当前账号去猜。

## 四、混了多个账号会怎样

同一天里如果不同场次由不同账号导出,说明里会显式写:

```
!! 注意:本日报混合了 2 个账号的数据(1(示例账号A)、2(另一个店))。
   不同店铺/账号的 GVM 不要相加或互相对比;若本应是一个账号,说明中途切过账号,
   请按 room_id 重新导出需要的那几场。
```

终端也会打印 `[daily] 注意: … 有 3 个账号导出的场次` 与 `[publish] 注意:…`。
这不是阻断(数据本身是各自真实的),只是提醒:**先确认这是不是你要的口径**。

## 五、怎么核对 / 怎么修

1. 看 `账号说明.txt`(或汇总表 `account` 列)是不是你预期的账号;
2. 不对就按 `room_id` 重导那几场:
   `python main.py export --date 2026-09-04 --account <正确账号>`(会覆盖同名 CSV 并更新归属);
3. 再跑 `python main.py daily --date 2026-09-04`,日报会按最新归属重写;
4. 需要彻底重来:删掉该日的 `live_20260904_*.csv`、`_compact.csv`、`_watch_min.csv` 后重新导出;
5. `_account_index.json` 可以安全删除(等同于"全部未知"),下次导出会重新建立。

## 六、涉及文件

| 文件 | 作用 |
|------|------|
| `accounts.py` | `account_label` / `account_identity` / `update_account_nickname`;索引读写 `record_export_account` / `export_accounts_for_day` / `load_account_index` / `distinct_accounts` |
| `auth.py` | `read_account_nickname`(登录时) + `sync_account_nickname`(导出路过页面时刷新登记) |
| `extractor/sessions.py` | `fetch_day_sessions(..., on_page=…)`:页面打开后回调一次(读账号名),回调异常不影响拉场次 |
| `extractor/trend.py` | `read_live(..., on_page=…)`:同上,用于单场/逐场导出 |
| `extractor/daily_stats.py` | 汇总表 `account` 列、`账号说明.txt`、混账号警告 |
| `main.py` | `_export_day` 记归属;`_daily_one_date` 读归属并传 `account_by_room` |
| `tests/test_daily_publish.py` | 汇总列/说明文件/混账号/未知 的离线回归 |
| `tests/test_accounts.py` | 展示名、索引往返、重复导出保留 first_at、坏索引容错 |
