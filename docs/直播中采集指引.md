# 直播中采集指引(看播量/千次观看成交金额分钟序列)

> 目的:在**下次房间正在直播时**,用一条命令对直播数据大屏做只读周期扫描,尝试
> 取到 **WatchCntTrend(直播间看播量)** 与 **gpm(千次观看成交金额,分钟级)** 等
> 分钟序列,补齐 `docs/GPM-观看次数口径结论.md` §3/§7 中"回放页只读未取到、待对拍"
> 的缺口,为"小时 GPM 的真实分母"提供证据。
> 本任务(t9)只做**脚本与文档准备 + 离线自测**,**不在本任务内执行真机直播采集**
> ——需要你在下次实际直播时另次运行(见下文"下次直播时如何运行")。

## 0. 为什么需要直播中采集

- 已确认(回放页,数值对拍):整场 GPM = PayGmv ÷ ServerWatchCntTd(累计看播次数,
  人次口径)× 1000;分钟序列位于 `room_minute_indicator`。
- 未闭合(口径结论 §7 遗留):**WatchCntTrend(直播间看播量)/gpm 分钟曲线在回放页的
  只读点击路径未取到**(t1);t6 补充探测(指标下拉展开)如仍未取到,直播中实时大屏
  的指标下拉/更多菜单是下一个候选入口。
- 若直播中取到 WatchCntTrend 且其分钟求和 ≈ ServerWatchCntTd(直播结束整场),即可把
  该序列作为"小时 GPM 分母(看播次数)分钟分解",实现**按小时 GPM = Σ小时gmv ÷
  Σ小时看播量 × 1000** 与整场 GPM 卡自洽。

## 1. 前提(全部满足才执行)

1. **本机已登录持久化 profile**:先运行 `python main.py login`(有头窗口,人工扫码
   一次;凭据仅存本地 `data/browser_profile`,不入库)。脚本复用该会话,不重新登录。
2. **账号对目标直播间有查看权限**(同一账号、直播数据大屏可见)。
3. **目标房间当前正在直播**(脚本只对"直播中大屏"有效;已结束/回放页不适用,
   脚本会提示页面状态为 ended)。
4. 已安装依赖:`pip install -r requirements.txt` 且 `python -m playwright install
   chromium`(如首次使用)。

## 2. 下次直播时如何运行(一行命令)

在项目根目录(douyin-live-gmv-export)执行:

```bash
python gpm_probe.py --live --room-id <直播中房间 room_id>
```

常用变体:

```bash
# 更长的直播:增加扫描波数与总时长上限
python gpm_probe.py --live --room-id <room_id> --waves 10 --interval-sec 20 --max-minutes 25
# 附加分钟序列原始备份(本地,不入库)
python gpm_probe.py --live --room-id <room_id> --raw-full
# 先看计划(不打开浏览器、不采集)
python gpm_probe.py --live --dry-run
```

参数说明:

| 参数 | 默认 | 含义 |
|------|------|------|
| `--live` | 关 | 直播中采集模式(需房间正在直播) |
| `--waves` | 6 | 周期扫描波次数 |
| `--interval-sec` | 20 | 波间间隔(秒) |
| `--max-minutes` | 15 | 总时长上限(分钟,到点优雅退出) |
| `--raw-full` | 关 | 另存观看系/成交金额分钟序列原始备份(不入库) |
| `--tag` | gpm_probe2 | 证据文件前缀(直播中证据默认与 gpm_probe2 同族) |
| `--room-id` | 无 | 必填:直播中房间 room_id |

## 3. 脚本会做什么(只读)

1. 复用已登录 profile,headful 打开 `https://eos.douyin.com/dp/liveScreen?room_id=<id>&tab=trend`。
2. 每波扫描(共 `--waves` 波,波间按 `--interval-sec` 等待,总时长受 `--max-minutes` 封顶):
   - 读自页面加载以来**新增**的 JSON 响应(`room_minute_indicator`/`key_index` 等);
   - DOM 只读扫描指标文本(千次观看成交金额/看播量/观看次数/GPM 等);
   - 在**白名单内**点选指标文案/下拉选项(每次点击只触发页面自身刷新);
   - 把所有出现过的 `room_minute_indicator` 序列 key 并入 `series_keys_total`(去重)。
3. 收口证据:重点标记 `WatchCntTrend`/`gpm`/观看系 target hits,做分钟求和 vs
   累计看播次数(ServerWatchCntTd)的闭合检查(直播中只作过程记录,最终以结束后整场为准)。
4. 证据写入 `data/probe/<tag>_<room_id>_<时间戳>.json`
   (schema_version=`gpm-live-1.0`,结构对齐 gpm_probe2:
   含 `waves`/`dom_metric_entries_seen`/`series_keys_total`/`target_hits`/`closure`);
   `--raw-full` 另存 `*_watch_raw.json`(本地,不入库)。

## 4. 预计时长

- 默认 6 波 × 20s + 首波页面加载(约 10–35s)+ 每波点选等待:
  **通常约 3–6 分钟**;参数上限 15 分钟。
- 直播较长/想要更多采样点,建议 `--waves 10` 以上(总时长相应加大)。

## 5. 失败时人工协助清单

脚本可能给出退出码与提示;遇到以下情况时的人工协助点:

| 现象 | 处理 |
|------|------|
| 退出码 2 + "无登录会话/打开浏览器失败" | 先 `python main.py login` 完成扫码,再重试 |
| 页面显示"已结束/回放"(session_state_hint=ended) | 房间当前不在直播;等直播开始后重跑 |
| 打开大屏超时/无网络 | 检查网络与账号权限(是否可人工打开该房间大屏) |
| 看不到 gpm/看播量曲线 | **人工点图表右上"更多菜单"图标或指标下拉**,再等脚本下一波自动记录;或人工点选"千次观看成交金额/直播间看播量"文案 |
| 长时间无新响应(series_keys_total 不增长) | 人工刷新页面后重跑;或加大 `--interval-sec`/`--max-minutes` |
| 脚本异常退出 | 已收集证据保留在 `data/probe/`,记录退出码与 stderr 反馈维护者 |
| 直播中途断流/重开 | 结束本次运行;若为新场次需新的 room_id 重跑(记录场次边界) |

脚本全部 UI 点击只在**白名单**内(观看/流量/成交/交易类);若下拉里出现疑似
商品/营销/违规/广告类选项,脚本会跳过且**不会点击**(见 §6)。

## 6. 合规与边界(与全项目一致)

- **只读**:复用已登录会话;不改写请求、不伪造响应、不做登录绕过与
  `a_bogus` 等签名逆向。
- **只操作账号已有权限数据**(本账号直播数据大屏)。
- **不收集商品/营销/违规/广告事件时间轴**:`product_trend`/`follow_product`/
  `marketing_data`/`local_ads_show_info`/`punish_info`/`lamp`/`roi2` 等端点
  **主体不落盘**(仅记 URL 名);UI 不点击 商品/营销/违规/视频/广告 类文案。
- 样例截断(前 3 后 3),不整场转储;`--raw-full` 原始备份仅限观看系/成交金额分钟序列。
- profile/凭据不提交、不入库;证据在 `.gitignore` 覆盖的 `data/probe/` 内。

## 7. 采集后

1. 把证据文件(`data/probe/<tag>_<room_id>_<ts>.json`,含 `_watch_raw.json` 如生成)
   保留供分析;若 WatchCntTrend 分钟求和 ≈ 直播结束后 ServerWatchCntTd,即闭合。
2. 更新 `docs/GPM-观看次数口径结论.md`:把 §3/§7 的"WatchCntTrend 待对拍"改为
   "直播中已取到 + 闭合结论",并把口径结论同步给小时 GPM 聚合实现(t2 模块约束解除)。
3. 如需跨场/长期口径稳定性,可在多次直播后复核 key/语义是否一致。
